# UI y experiencia

## Dirección visual vigente · v0.4

- Home = **dashboard fijo de widgets**, no landing y no gestor de ventanas.
- Modo claro como referencia actual.
- Paleta principal: blanco, negro y rojo.
- Inspiración cromática: uso expresivo del rojo en el cine de Pedro Almodóvar, sin copiar composiciones concretas.
- Superficies translúcidas: redondeadas, con blur y profundidad tipo Liquid Glass.
- Superficies opacas: geometría más recta y sobria.
- Widgets: pocos, ligeros y con jerarquía clara.
- Sidebar: colapsable en escritorio y drawer en móvil.
- Nada de ventanas libres, drag-and-drop de paneles o escritorio flotante en la home.

## Chats


### Composer y envíos · v0.4

El chat de agentes adopta patrones de clientes maduros como LibreChat sin copiar su interfaz: Enter envía en escritorio; Shift+Enter crea salto; selector, pegado y arrastre de adjuntos; cola de mensajes mientras existe una ejecución; detener recupera el turno todavía no entregado; estados de envío visibles; copiar, editar/reutilizar y reintentar mensajes.

Límite inicial de demo: 8 adjuntos y 25 MiB por archivo. La demo solo conserva metadatos de archivo en memoria; producción hará upload autorizado y transformará los adjuntos en referencias persistentes antes de invocar el runtime.

### Historial por proyecto

Cada proyecto muestra su propio historial dentro del chat:

- **Fijadas**: conversaciones importantes al principio.
- **Recientes**: ordenadas por última actividad.
- **Archivar**: retira de recientes sin borrar.
- **Nueva conversación**: crea otro chat dentro del mismo proyecto y con el mismo agente por defecto.

Un chat de proyecto se conserva automáticamente. Fijar o archivar no cambia permisos, conocimiento ni contexto del agente.

### Nuevo chat · Con conocimiento

Debe mostrar claramente:
- que dispone de conocimiento personal;
- qué herramientas están habilitadas;
- qué agente/runtime lo atiende.

Al cerrar o durante el chat:
- Guardar conversación;
- Guardar conocimiento relevante;
- Mover a categoría;
- Eliminar.

### Nuevo chat · Sandbox

Indicador persistente de aislamiento.

Acciones:
- Descartar;
- Guardar como General;
- Continuar en Vivienda;
- Continuar en Universidad;
- Continuar en Finanzas;
- Continuar en Personal;
- elegir otra categoría.

La UI nunca representa "Continuar en..." como cambio de permisos del chat actual: debe crear una conversación nueva.

## Agentes

Cada agente muestra:
- scope de conocimiento;
- herramientas;
- cuentas/credenciales utilizables;
- Computer Use;
- reglas de aprobación.

Estas propiedades se cargan desde API/configuración, no desde constantes del frontend.

## Archivos

Lisa presenta su propio explorador.

Nextcloud queda detrás de:
- WebDAV;
- OCS;
- CalDAV;
- servicios de versionado/sync.

La UI puede cambiar completamente sin migrar archivos.

## Calendario

Vista propia día/semana/mes.

Debe poder combinar calendarios de distintos adapters en el futuro.

## Tareas

Vista Inbox + proyectos/categorías.

La UI consume `TaskService`, por lo que puede cambiar entre Nextcloud Tasks/CalDAV y Vikunja sin rehacer el frontend.

## Computer Use

Cuando exista una sesión:

```text
[ Abrir Desktop ] [ Take control ] [ Stop ]
```

Estados visibles:
- Agent controlling;
- Human controlling;
- Waiting for human;
- Paused;
- Finished.

## Cuentas

No se muestran secretos.

Ejemplo:

```text
Endesa
Usable by: Vivienda
Secret: managed by 1Password
Last use: ...
Policy: login/download invoices
```

## Developer Mode

Vista futura:

```text
┌──────────────────────┬──────────────────────────┐
│ Coding agent         │ Live preview             │
├──────────────────────┴──────────────────────────┤
│ Terminal / tests / git diff                     │
│                                                 │
│ [Apply] [Discard]                               │
└─────────────────────────────────────────────────┘
```

Flujo:
1. crear branch;
2. modificar código;
3. tests;
4. preview aislada;
5. diff;
6. aprobación;
7. merge/deploy.

## Principio de diseño

La UI no es Lisa. Es un cliente de Lisa.

Debe ser posible borrar y reescribir `apps/web` sin perder conocimiento, agentes, chats, archivos, calendario, tareas o permisos.
